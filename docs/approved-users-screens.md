# Настройки — Потребители: одобрен дизайн

**Одобрено от собственика на 03.10.2026.** Това са водещите три макета за
внедрения екран, а не снимки с реални клиентски данни.
Публичните копия използват примерни имейли и организация. Подредбата,
цветовете, формите и разрешените действия не се заменят без ново одобрение.

## Супер администратор

В таблицата с хора действието е „Преглед“. Ролята и разрешените Обекти са
текст, не полета за редакция. Личните услуги се показват със статус, без
бутони за разрешаване/отнемане: тях управлява администраторът на организацията.
Държавите за „Цени ден напред“ са отделни редове с отметка и пояснение.
Неподдържана за събиране зона остава неактивна; оформлението не дава право.

### Задължителни визуални проверки

Името на страницата е „Потребители“. Активната роля идва от проверения
акаунт, не от демонстрационен профил. Услугите се показват в ред:
Цени ден напред, Графики и визуализации, Анализ, Метеорология, Прогнозиране.
Всяка има отделни име, пояснение, статус и действие. „Предстои“ не дава
право за използване и бутонът остава неактивен.

На телефон полетата имат видими граници, а бутоните са поне 44 px високи.
Проверката включва 390, 1024 и 1440 px. Непроверени права или недостъпен
API се изписват като грешка, никога като липсващи потребители или услуги.
За наблюдател директният адрес показва собствената самоличност и връзка
„Към моите услуги“, без административни данни.

Това е приемателен критерий, не автоматично потвърждение за внедряване.

Само собствената активна роля. Избор на одобрена организация → пет услуги →
заявки от организации → преглед на хората → нова покана → история →
одобрени организации и услуги. Супер админ разрешава организационни услуги
и зона, но не заобикаля организационния админ за личните услуги.

## Администратор на организация

Пет услуги → нова покана → история → одобрени хора с пет колони →
разгъваем редактор → заявки от потребители. Колоните са **Име/имейл, Роля,
Обекти, Услуги, Действия**. На телефон редът става карта.
Админът разрешава услуги поотделно, включително за себе си. Обектите се
записват отделно от услугите и се проверяват в OpenRemote.

## Потребител — наблюдател

„Потребители“ **не е в менюто**. Директен адрес показва отказ, без чужди хора
или данни. Личните заявки са в „Услуги“, а разрешените Обекти — в „Обекти“.
Долните части на макета показват тези отделни лични изгледи за сравнение,
не административни секции, разрешени на наблюдателя.

## Поддържа ли се от бекенда?

Проверка на кода и тестовете от 03.10.2026: **148 успешни теста, 1 пропуснат,
0 неуспешни**. Това не е доказателство за завършен тест с реалните три акаунта.

| Действие от макета | Състояние |
| --- | --- |
| Избор на активна организация; каталог с пет услуги | API е наличен и защитен |
| Организационно разрешение/отнемане и BG зона | API е наличен; личните права не се включват автоматично |
| Лично разрешение/отнемане, включително за админа | API е наличен; изисква организационно право |
| Заявка, одобрение, отхвърляне | API е наличен с отделни нива и проверки |
| Отмяна на собствена организационна заявка от админ | API е наличен |
| Списък с хора, роли, Обекти и услуги | API е наличен; връзките към OpenRemote се проверяват |
| Покана, история, повторно изпращане на неприета покана | API е наличен |
| Имейл след действие | Има опашка и тестове; реално получаване на писмо не е тествано в тази проверка |
| Отмяна на лична заявка / спиране на лична услуга | Внедрени защитени API и бутони; само личен обхват |
| Новият лейаут в живия портал | **Публикуван на 03.10.2026** — Настройки → Потребители |

Първоначалната проверка откри липсваща лична отмяна в API.
След изричното потвърждение по-долу са добавени защитени действия и тестове.
Макетът сам по себе си не доказва работещо внедряване.

## Потвърдено уточнение: отмяна и спиране

Собственикът потвърди следното, което заменя по-ранната отворена забележка:

- „Отмени заявката“ променя в базата само собствената чакаща заявка на „Отменена“.
- „Спри услугата“ след потвърждение премахва само личното разрешение.
- Разрешението за организацията, другите хора и връзките към Обекти не се променят.
- Повторното включване изисква ново одобрение от организационния админ.
- При грешка няма местно „успешно“ спиране; състоянието се проверява отново.

Новите API и бутони са внедрени. 82 браузърни и 29 server-render/API проверки
на фронтенда минават; автоматичните проверки са успешни. Публикуването
и работоспособността на бекенда са проверени след обновяването.
Проверката с четене потвърди каталога, хората и OpenRemote връзките на
съществуващите организации. Не са променяни реални права за тест.
**Приемането с трите реални акаунта остава отделна проверка.**
Не е нужна нова миграция за личното спиране.

## Правила за изпълнение

- Реалният екран следва този макет, а не друга по-стара версия.
- Ролята се извежда от проверената самоличност; няма превключвател на роли.
- Макетните имена, Обекти и статуси никога не стават реални данни.
- API грешка е „Не успяхме да проверим достъпа“, не „Нямате права“.
- Всяко записване изисква backend проверка; след успех се опреснява редът.
- Одобрение на услуга не изисква второ „Приемам“.
- Празен списък, зареждане, отказ и грешка се проверяват отделно.
- Преди приемане: реални три роли, мобилен/desktop, BG/EN, уведомления и отказ към чужда организация.
